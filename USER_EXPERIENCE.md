# User experience: L2Code

A reference and learning tool for beginning programmers. Owns journeys and feedback; visual rules live in [STYLE](STYLE.md). Apply review only to the affected workflow.

## Current journeys

- Launch into Learning Modules with Grade 0 selected. Choose a grade and expand sections progressively. Grades 0–2 have content; Grades 3–9 display coming-soon content. Preserve shared accordion behaviour and reading-panel scroll handling.
- Switch to Programming Vocabulary. All five category filters default on; no term is selected initially, so the detail pane displays How to Use This Reference.
- Type a prefix or recognised alias/syntax form, toggle categories, then select an entry to read it. Clearing search restores the query and focuses the field. Keep counts and selection consistent with filtering.
- Follow related-term links and use breadcrumbs to return along the reading path. Direct result selection and search changes clear the breadcrumb trail.

Navigation, queries and expanded sections are browser-memory state, not saved progress. Do not imply that progress survives a reload.

## Feedback and recovery

Zero results offers a broader search or clearing the field; retain that direct recovery. Missing vocabulary produces the existing load-failure feedback. Do not describe a retry control or complete offline asset bundle as implemented. A broken payload/fetch path may prevent event binding because vocabulary initialisation precedes binding; account for that boundary when changing loading behaviour.

Do not execute educational code examples. Keep code readable and distinguish article metadata from navigable related terms. Current direct-file use is limited by three missing embedded sources, as documented in DATA. Preserve accessible names, keyboard/touch controls and state beyond colour.

## Review timing

Ask before implementing materially ambiguous interaction models. For a substantial new journey, show a usable slice for owner review before broad polish. Minor changes preserving established flows need no manufactured approval gate. Check newcomer discoverability, consequences, visible results and recovery only where affected. Use available rendering or user device feedback and state what was actually exercised.

Update only for lasting workflow rules; no routine UX audit files.
